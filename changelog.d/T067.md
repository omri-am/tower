- `tower-notify` no longer needs `osascript`. It uses the first channel that applies. When
  `TOWER_NOTIFY_COMMAND` is set and not empty, it runs that command as one executable path, not
  through a shell, with two arguments: `tower: <title>` and `<message>`. It exits with the
  command's status and uses no other channel. Otherwise, when `osascript` is on `PATH`, it shows
  the macOS notification as before. Otherwise, when `notify-send` is on `PATH` and `DISPLAY` or
  `WAYLAND_DISPLAY` is not empty, it runs `notify-send` with the same two arguments and exits
  with its status. Otherwise it writes `tower: <title>: <message>` and a terminal bell to stderr
  and exits 0. Before, with two or more arguments, it always ran `osascript`, whatever the value
  of `TOWER_NOTIFY_COMMAND`. Where `osascript` was not on `PATH`, as on Linux, each such call
  exited 127 and showed no notice, and `tower-watch` ignored that failure. On a Mac with
  `TOWER_NOTIFY_COMMAND` set and not empty, the command now runs in place of the macOS
  notification. With fewer than two arguments, it prints the same usage line and exits 1, as
  before.
