## Reviews — `reviews/T###/fix-<N>.md`

An implementor runs at most three review rounds, so a fix for a round-3 finding has no round
left. A fix check closes that gap. Before a PR merges, the orchestrator has a fresh reviewer
read every commit after the last reviewed commit, and it records the result in
`reviews/T###/fix-<N>.md`, with N from 1. The implementor keeps its own rounds.

**Rule.** The merged head is always a reviewed head. The last reviewed commit is the
`reviewed_commit` of the card's newest record, or, with no record, the commit of the
handoff's last `- Round <N> reviewed` line. The head is reviewed when it equals the last
reviewed commit and the newest record, if any, has `verdict: clean`. When the head equals the
`reviewed_commit` of a newest record that says `changes`, no fix check runs until the head
changes or the handoff answers that record.

**Range.** A fix check reads the commits from the last reviewed commit to the PR head. It
reads the PR's full diff from its merge base instead when the handoff names no reviewed
commit or the range holds a merge commit. `from_commit` is the start of the range. When the
answer to a `changes` record rejects every finding and the head did not change, the next fix
check reads the same range as that record.

**Cap.** At most three fix checks for each PR, outside the implementor's three rounds. When
the third returns `changes`, the orchestrator notifies the owner and runs no more fix checks
for that PR. It does the same when a fix check returns `changes` on a finding that the
implementor already rejected.

```markdown
---
task: T###
pr: <url>
from_commit: <40-hex>       # start of the range
reviewed_commit: <40-hex>   # the PR head the reviewer read
reviewer: <host> / <agent> / <model>
verdict: clean | changes
date: <ISO 8601>
---

## Findings

- [important] path/to/file:12 — finding, with its evidence
```

Each finding has a severity: `critical`, `important` or `suggestion`. The verdict is `clean`
when no finding is critical or important. A check with no finding says `None.` under
`## Findings`.

**Answer.** The implementor answers a `changes` record in its handoff, under *What was done*,
with one line for each record:

```
- fix-<N> answer: finding 1 fixed in <40-hex commit>; finding 2 rejected: <reason>
```

Findings are numbered by their order under `## Findings` in the record. The line covers every
critical or important finding.
