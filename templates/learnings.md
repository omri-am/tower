# Learnings

> Read the entries your card selects, not the whole file: `tower-learnings --for T###`
> (your dispatch prompt already contains that selection).
> Format: `- [category] lesson — why it matters (T###)`, where `T###` is the task that paid
> for it. Implementors propose candidates in handoffs; the orchestrator is the only writer.
>
> **Filing rule.** Most rot is a misfiled entry. Before adding one, place it:
> a fact about the system → `design.md`; a rule true for every tower project → the
> `tower-implementor` skill or the card template; a project-specific way of working or
> failure mode → here. This file is a staging area with exits, not an accumulator.
>
> **Budget: 60 entries** (`tower-learnings --check`). At the budget, adding requires
> retiring one to `learnings-archive.md` — retire with a reason, never delete.
>
> Sections are path scopes, matched against the card's `## File ownership`. Unscoped
> headings (`## Always` and anything not starting with `scope:`) go into every prompt.
